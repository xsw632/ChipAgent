Create `CLAUDE.md` with these required sections (per PLUG-04 and research findings):

1. **Project Description** -- What ChipAgent is, its core value proposition
2. **Tech Stack** -- Chisel 7.2.0, Scala 2.13.16, sbt, firtool (auto-managed), Verilator 5.008
3. **Directory Structure** -- Where files live:
   - `.claude-plugin/` -- Plugin manifest
   - `skills/` -- Slash command definitions
   - `agents/` -- Subagent definitions (future phases)
   - `hooks/` -- PostToolUse automation
   - `scripts/` -- Build automation scripts (compile.sh, setup.sh, lint.sh, simulate.sh)
   - `chisel-project/` -- sbt project root
   - `chisel-project/src/main/scala/chipagent/` -- Chisel source code
   - `generated/` -- Emitted Verilog/SystemVerilog output
   - `sim/logs/` -- Simulation logs and reports
4. **File Path Conventions** -- All Scala sources in `chipagent` package, output to `generated/`, logs to `sim/logs/`
5. **Interface Specs** -- Chisel module IO bundle conventions, port naming (UInt, SInt, Bool), IO bundle pattern:
   ```scala
   val io = IO(new Bundle {
     val portName = Input(UInt(width.W))
     val portName = Output(UInt(width.W))
   })
   ```
   Note: Chisel wraps all ports in `io` bundle, so Verilog ports become `io_<portName>`
6. **Build Commands** -- `scripts/compile.sh` for compilation, `sbt --batch "runMain chipagent.Generate"` for direct sbt
7. **Chisel API Rules** -- CRITICAL rules:
   - Import `chisel3._` for DSL, `circt.stage.ChiselStage` for emission
   - Use `emitSystemVerilogFile` (NOT `emitVerilog` which is deprecated/removed)
   - Dependency is `org.chipsalliance::chisel` (NOT `edu.berkeley.cs::chisel3`)
   - Do NOT set `CHISEL_FIRTOOL_PATH` -- firtool is auto-managed by firtool-resolver
   - Always use `--batch` flag with sbt in scripts
8. **Pipeline Overview** -- Stages from NL input to verified Verilog
