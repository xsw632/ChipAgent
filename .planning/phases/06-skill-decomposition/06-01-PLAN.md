Create three skill directories and SKILL.md files using the modern Claude Code skill format.

**skills/compile/SKILL.md:**
- Frontmatter: `name: compile`, description (1-2 sentences about compiling Chisel to Verilog for a named module), `disable-model-invocation: true`, `allowed-tools: Bash, Read`
- Instructions section:
  1. Extract module name from `$ARGUMENTS`. If empty, ask user for a module name.
  2. Validate: module name should be PascalCase (first letter uppercase, no spaces/hyphens).
  3. Set workspace path: `workspace/$ARGUMENTS`
  4. Find the plugin root by locating the directory containing `.claude-plugin/plugin.json` (do NOT use `${CLAUDE_PLUGIN_ROOT}` literally in the markdown -- it does not interpolate in skill files per known issue #9354).
  5. Run: `<plugin-root>/scripts/compile.sh workspace/<ModuleName>`
  6. On success: list generated files in `workspace/<ModuleName>/generated/`
  7. On failure: show the build error output and suggest checking the Chisel source at `chisel-project/src/main/scala/chipagent/<ModuleName>.scala`
- Input: `$ARGUMENTS` -- module name (PascalCase)
- Output: Generated Verilog files in `workspace/<ModuleName>/generated/`

**skills/lint/SKILL.md:**
- Frontmatter: `name: lint`, description (1-2 sentences about running Verilator lint on generated Verilog), `disable-model-invocation: true`, `allowed-tools: Bash, Read`
- Instructions section:
  1. Extract module name from `$ARGUMENTS`. If empty, ask user.
  2. Check that `workspace/<ModuleName>/generated/` exists and contains .v files. If not, tell user to run `/chip-agent:compile <ModuleName>` first.
  3. Find plugin root (same approach as compile: locate `.claude-plugin/plugin.json`).
  4. Run: `<plugin-root>/scripts/lint.sh workspace/<ModuleName>`
  5. On success: report lint passed. If `workspace/<ModuleName>/generated/lint-warnings.log` is non-empty, list suppressed warnings.
  6. On failure: show Verilator lint errors and suggest fixing the Chisel source (not the generated Verilog).
- Input: `$ARGUMENTS` -- module name (PascalCase)
- Output: Lint pass/fail report with any suppressed warnings

**skills/simulate/SKILL.md:**
- Frontmatter: `name: simulate`, description (1-2 sentences about running Verilator simulation for a named module), `disable-model-invocation: true`, `allowed-tools: Bash, Read`
- Instructions section:
  1. Extract module name from `$ARGUMENTS`. If empty, ask user.
  2. Check prerequisites: `workspace/<ModuleName>/generated/` must contain .v files AND `workspace/<ModuleName>/sim/tb_<ModuleName>.cpp` must exist. If Verilog missing, tell user to run `/chip-agent:compile`. If testbench missing, tell user to run `/chip-agent:testbench`.
  3. Find plugin root (same approach as compile).
  4. Run: `<plugin-root>/scripts/simulate.sh workspace/<ModuleName>`
  5. On success: read `workspace/<ModuleName>/sim/logs/sim_result.log` and present formatted results (pass count, fail count, per-test breakdown).
  6. On failure: read `workspace/<ModuleName>/sim/logs/sim_result.log` for failure details and suggest checking the testbench or Chisel source.
- Input: `$ARGUMENTS` -- module name (PascalCase)
- Output: Simulation results from `workspace/<ModuleName>/sim/logs/sim_result.log`

**Critical constraints:**
- Do NOT use `${CLAUDE_PLUGIN_ROOT}` directly in SKILL.md text. Instead instruct Claude to find the plugin root by locating the `.claude-plugin/plugin.json` ancestor directory (e.g., "Determine the plugin root directory by finding the nearest ancestor containing `.claude-plugin/plugin.json`").
- Keep descriptions concise (1-2 sentences) to stay within the skill description budget.
- Each skill does ONE thing only. Compile does not lint. Lint does not simulate.
