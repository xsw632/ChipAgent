Create two skill directories and SKILL.md files using the modern Claude Code skill format.

**skills/requirement-parser/SKILL.md:**
- Frontmatter: `name: requirement-parser`, description (1-2 sentences about parsing NL hardware descriptions into structured spec.json), `disable-model-invocation: true`, `allowed-tools: Read, Write, Bash, Grep, Glob`
- Instructions section:
  1. The user provides a natural language hardware description as `$ARGUMENTS`.
  2. If `$ARGUMENTS` is empty, ask the user to describe the hardware module they want to create.
  3. Read the requirement-parser agent definition at `agents/requirement-parser.md` (relative to the plugin root -- find plugin root by locating `.claude-plugin/plugin.json`).
  4. Follow the agent's instructions to parse `$ARGUMENTS` into a structured JSON spec. The agent returns ONLY JSON.
  5. Validate the JSON output:
     - `moduleName` is present and PascalCase
     - `type` is "simple" or "complex"
     - All ports have `direction`, `type`, and `width`
     - For simple specs: verify `ports` array is non-empty
     - For complex specs: verify `topModule.submodules` matches names in `modules[]`
  6. Create the workspace directory structure: `mkdir -p workspace/<moduleName>/generated workspace/<moduleName>/sim/logs`
  7. Write the JSON spec to `workspace/<moduleName>/spec.json` using the Write tool. This is CRITICAL -- the agent returns JSON to conversation output; the skill must capture it and write to disk.
  8. Present a summary of the parsed spec to the user:
     - Module name and description
     - Port count (inputs/outputs)
     - Operation count (if any)
     - File location: `workspace/<moduleName>/spec.json`
- Input: `$ARGUMENTS` -- natural language hardware description
- Output: `workspace/<ModuleName>/spec.json` containing structured specification

**skills/testbench/SKILL.md:**
- Frontmatter: `name: testbench`, description (1-2 sentences about generating a C++ Verilator testbench from a module's spec.json), `disable-model-invocation: true`, `allowed-tools: Read, Write, Bash, Grep, Glob`
- Instructions section:
  1. Extract module name from `$ARGUMENTS`. If empty, ask the user for a module name.
  2. Read `workspace/<ModuleName>/spec.json` using the Read tool. If the file does not exist, STOP and tell the user: "No spec.json found for <ModuleName>. Run `/chip-agent:requirement-parser` first to create a specification."
  3. Read the testbench-generator agent definition at `agents/testbench-generator.md` (relative to plugin root).
  4. Follow the agent's instructions using the spec JSON content to generate a C++ testbench.
  5. IMPORTANT: Override the agent's default output path. Write the testbench to `workspace/<ModuleName>/sim/tb_<ModuleName>.cpp` (NOT `sim/tb_<ModuleName>.cpp` which is the flat-mode default). Ensure the directory exists: `mkdir -p workspace/<ModuleName>/sim`.
  6. After writing the testbench, confirm to the user:
     - Testbench path: `workspace/<ModuleName>/sim/tb_<ModuleName>.cpp`
     - Test vector count
     - Next step: "Run `/chip-agent:simulate <ModuleName>` to execute the testbench"
- Input: `$ARGUMENTS` -- module name (PascalCase)
- Output: `workspace/<ModuleName>/sim/tb_<ModuleName>.cpp`

**Critical constraints:**
- Do NOT use `${CLAUDE_PLUGIN_ROOT}` directly in SKILL.md text (does not interpolate per GitHub issue #9354).
- The requirement-parser skill MUST explicitly write spec.json to disk. The agent returns JSON to conversation output -- it does NOT write files itself.
- The testbench skill MUST read spec.json from disk, NOT from conversation context. This enables standalone invocation in a fresh session.
- The testbench skill MUST write to `workspace/<Module>/sim/tb_<Module>.cpp`, overriding the agent's flat-mode default of `sim/tb_<Module>.cpp`.
- Both skills need `allowed-tools` that include Read and Write (for file I/O with workspace).
