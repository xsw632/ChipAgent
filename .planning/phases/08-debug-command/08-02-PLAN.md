Create `scripts/parse_vcd.py` -- a lightweight, self-contained Python VCD parser using ONLY stdlib modules (json, re, sys, argparse). No pip dependencies. Per user decision, this is inspired by waveform_mcp's architecture but minimal.

**Architecture (per RESEARCH.md recommendations):**

Implement a `VCDParser` class with:
1. `__init__(self, vcd_path)` -- parses the VCD file on construction
2. `_parse(self)` -- single-pass VCD parsing:
   - Parse header sections: `$date`, `$version`, `$timescale` (between keyword and `$end`)
   - Parse signal definitions: track `$scope module <name>` / `$upscope` to build hierarchical scope stack. Parse `$var wire <width> <symbol> <name> $end` lines to build signal table mapping symbol -> {path: "scope.scope.name", width: int}. Also build reverse mapping path -> symbol.
   - Parse value changes section: after `$enddefinitions $end` and `$dumpvars` / `$end`, parse lines starting with `#<timestamp>` to set current time. Parse value change lines: single char + symbol for scalar signals (e.g., `1!`), `b<binary> <symbol>` for vector signals. Store as transitions dict: symbol -> [(time, value), ...] sorted by time.
3. `get_value_at_time(self, signal_path, timestamp)` -- find signal by suffix match (to handle hierarchical names like `TOP.VALU.io_result` when queried as `io_result`). Binary search on transitions list for most recent change <= timestamp. Return the value as a string.
4. `get_signals_at_time(self, signal_paths, timestamp)` -- call get_value_at_time for each signal path, return dict {signal: value}.
5. `list_signals(self)` -- return all signal full paths.
6. `search_signals(self, keyword)` -- return signal paths where keyword appears as a suffix (case-insensitive).

**CLI interface (argparse):**
```
python3 parse_vcd.py --vcd <path.vcd> --signals sig1 sig2 ... --time <t1> [t2 ...]
python3 parse_vcd.py --vcd <path.vcd> --list-signals
```

**Output:** JSON to stdout. For `--signals`/`--time` mode:
```json
{
  "1": {"io_result": "00001000", "io_inputA": "00000101"},
  "2": {"io_result": "00000111", "io_inputA": "00001010"}
}
```
Values are in binary string format as they appear in VCD. For `--list-signals` mode:
```json
{"signals": ["TOP.VALU.io_inputA", "TOP.VALU.io_inputB", ...]}
```

**Error handling:**
- If VCD file not found: print JSON error to stderr, exit 1
- If signal not found: include null for that signal in output, do not crash
- If timestamp has no data: return most recent known value (last-value semantics)

**Make executable:** Add shebang `#!/usr/bin/env python3` and set executable permission.

**Key pitfalls to handle (from RESEARCH.md):**
- Signal names in VCD use hierarchical naming (e.g., `TOP.V<Module>.io_result`). The parser MUST search by suffix, not exact match.
- Use `bisect` module for efficient binary search on sorted transition lists.
- For ChipAgent's use case (small modules, <100 tests), loading the full VCD into memory is fine.

The agent body should define:

**## Role**
You are a simulation failure analyst for ChipAgent. Given a module name and its workspace artifacts, you cross-reference four sources (spec.json, Chisel source, sim_result.log, VCD waveform) to diagnose test failures and suggest targeted Chisel code fixes.

**## Artifact Loading (with graceful degradation per CONTEXT.md decision)**

Define the 4 artifacts and their requirement levels:
1. `workspace/<Module>/spec.json` -- REQUIRED. If missing: STOP with error "No spec found. Run `/chip-agent:requirement-parser` first."
2. `chisel-project/src/main/scala/chipagent/<Module>.scala` -- REQUIRED. If missing: STOP with error "No Chisel source found for <Module>."
3. `workspace/<Module>/sim/logs/sim_result.log` -- SOFT REQUIRED. If missing: STOP with suggestion "No simulation results. Run `/chip-agent:simulate <Module>` first."
4. `workspace/<Module>/sim/logs/<Module>.vcd` -- OPTIONAL. If missing: continue with log-only analysis, note "VCD not found; performing log-only analysis without signal traces."

**## Analysis Steps**

1. **Parse sim_result.log:** Use regex to extract test results. Pattern: `[TEST N] <op_name>: <inputs> | expect=X got=Y | PASS|FAIL`. Also extract the RESULT summary line. Identify all FAILED tests.

2. **If all tests passed:** Report "All tests passed. No failures to analyze." and exit.

3. **Map failures to spec operations:** For each failed test, find the matching operation in spec.json by `op_name` == `operations[].name`. Extract the opcode, expression, and any relevant spec details.

4. **Extract VCD signal values (if VCD available):** For each failed test number N, calculate the VCD timestamp (test N maps to sim_time=N, since the testbench increments sim_time by 1 per test starting from 0, but dumps AFTER eval so test 1 is at sim_time=0). Call the parse_vcd.py script via Bash:
```bash
python3 <plugin-root>/scripts/parse_vcd.py \
  --vcd workspace/<Module>/sim/logs/<Module>.vcd \
  --signals io_result io_inputA io_inputB io_op \
  --time <timestamp>
```
Adjust signal names based on the spec.json ports. The parser handles hierarchical VCD names via suffix matching.

5. **Map failures to Chisel source:** Read the Chisel source file. For each failed operation, search for the `is(<opcode>.U)` block in a `switch` statement. Extract the relevant Chisel logic block. Use Grep to find the pattern.

6. **Generate fix suggestions:** For each failure, compare expected vs got values. Based on the spec expression and the Chisel implementation, suggest specific code fixes. Fix suggestions target Chisel source as primary (per CONTEXT.md decision). If the testbench expected value appears wrong (e.g., misunderstanding of unsigned overflow), flag it but still point to Chisel.

7. **Do NOT auto-apply fixes.** The debug command diagnoses and suggests; the user decides whether to apply.

**## Report Structure**

Write the report to `workspace/<Module>/debug/debug_report.md` using the Write tool. Create the directory first (`mkdir -p workspace/<Module>/debug`).

The report MUST follow this structure (per CONTEXT.md decision for structured sections):

| io_op | N |

(If VCD not available, omit Signal Trace section and note: "VCD trace not available")

**Spec Reference:** Operation "<OP_NAME>" (opcode N)
  Expression: `<chisel expression from spec.json>`

**Chisel Source:** `chisel-project/src/main/scala/chipagent/<Module>.scala`
  Relevant block: `is(<opcode>.U) { ... }`
