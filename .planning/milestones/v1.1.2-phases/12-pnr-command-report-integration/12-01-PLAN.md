Create `agents/pnr-report-formatter.md` following the established agent pattern from `agents/debug-analyzer.md`.

YAML frontmatter:
```yaml
---
name: pnr-report-formatter
description: "Formats raw PnR reports (timing, power, area, synthesis stats) into a human-readable verification summary"
tools: [Read, Bash]
model: inherit
---
```

Agent body structure:

1. **Role section**: "You are a PnR report formatter for ChipAgent. Given a module name and its workspace PnR artifacts, you parse raw report files and produce a formatted human-readable verification summary."

2. **Artifact Loading section**: Table listing the 5 report files to read, all from `MyDesign/<Module>/workspace/pnr/reports/`:
   - `synth_stat.txt` (REQUIRED) -- parse "Number of cells:" line and "Chip area for module" line
   - `timing.rpt` (REQUIRED) -- parse final "slack (MET|VIOLATED)" line for WNS, extract Path Group for clock name
   - `power.rpt` (REQUIRED) -- parse "Total" row for aggregate power in Watts, parse bottom percentage line for internal/switching/leakage split
   - `area.rpt` (REQUIRED) -- parse "Design area XXX um^2 XX% utilization" line
   - `drc.rpt` (OPTIONAL) -- if non-empty, count violations
   Each file: check exists and is non-empty before parsing. For missing files, output "N/A" for that section.

3. **Parsing Steps**: Numbered steps (Step 1 through Step 5) for each report file:
   - Step 1: Parse synth_stat.txt -- extract cell count from "Number of cells: NNN" and synthesis area from "Chip area for module '\\<Module>': NNN.NNN"
   - Step 2: Parse timing.rpt -- extract slack value and MET/VIOLATED status from last "slack" line. WNS is the slack value. For TNS, grep for "tns" line if present, otherwise report "0.00 ns" (single path reports have no TNS). Extract clock name from "Path Group:" line.
   - Step 3: Parse power.rpt -- extract Total row values. Convert from Watts to microwatts (multiply by 1e6). Parse bottom percentage line for internal/switching/leakage percentages.
   - Step 4: Parse area.rpt -- extract area in um^2 and utilization percentage from the "Design area" line.
   - Step 5: Parse drc.rpt -- if file exists and is non-empty, count violation lines. If empty or missing, report "Clean (0 violations)".

4. **Report Template**: The exact output format (verbatim template the agent must follow):

```
=== PnR Verification Report: <ModuleName> ===

Timing:     <PASSED|FAILED> (<MET|VIOLATED>)
  WNS:      X.XX ns
  TNS:      X.XX ns
  Clock:    <clock_name> @ <period> ns

Power:
  Internal:    XX.X uW  (XX.X%)
  Switching:   XX.X uW  (XX.X%)
  Leakage:     XX.X uW  (XX.X%)
  Total:       XX.X uW

Area:
  Synthesis:   XXX um^2
  Post-PnR:    XXX um^2 (XX% utilization)
  Cell Count:  XXX

DRC:         Clean (0 violations)

Artifacts:
  Netlist:     MyDesign/<Module>/workspace/pnr/<Module>.synth.v
  Routed DEF:  MyDesign/<Module>/workspace/pnr/<Module>.routed.def
  GDS:         MyDesign/<Module>/workspace/pnr/<Module>.gds
  Reports:     MyDesign/<Module>/workspace/pnr/reports/
```

5. **Anti-Patterns section**:
   - DO NOT write the report to a file -- output it directly in the conversation
   - DO NOT report power in raw Watts -- always convert to microwatts (uW)
   - DO NOT crash on missing report files -- use "N/A" gracefully
   - DO NOT parse generated Verilog or Chisel source -- this agent reads PnR reports only

**Part A: Create `skills/pnr/SKILL.md`**

Follow the exact pattern from `skills/workflow/SKILL.md`. Structure:

YAML frontmatter:
```yaml
---
name: pnr
description: "Run Yosys synthesis + OpenROAD PnR + KLayout GDS export on compiled Verilog. Produces timing, power, area reports and GDS file with auto-retry on failure."
disable-model-invocation: true
allowed-tools:
  - Bash
  - Read
  - Write
  - Edit
  - Grep
  - Glob
---
```

Skill body:

1. **Title and description**: `# chip-agent:pnr` -- Physical implementation pipeline: synthesize compiled Verilog, run place-and-route, export GDS, and produce a formatted PnR verification report.

2. **Usage section**:
```
/chip-agent:pnr <ModuleName>
```
Example: `/chip-agent:pnr ALU`

3. **Instructions section**: "Determine the plugin root directory by finding the nearest ancestor directory of this skill file that contains `.claude-plugin/plugin.json`. Use that directory as the base for all relative paths below."

4. **Pipeline section** with 4 steps:

**Step 0 -- Verify Prerequisites**
- Set `PLUGIN_ROOT`, `MODULE` from $ARGUMENTS (first argument, the bare module name)
- Check that `MyDesign/<ModuleName>/workspace/generated/<ModuleName>.v` exists
- If missing: STOP with clear message: "No compiled Verilog found for <ModuleName>. Run `/chip-agent:compile <ModuleName>` or `/chip-agent:workflow <description>` first."
- If exists: continue

**Step 1 -- Synthesize (with auto-fix context)**
- Run: `<plugin-root>/scripts/synth.sh <ModuleName>`
- On success (exit 0): continue to Step 2
- On failure (non-zero exit): Read error output. Synthesis errors are typically RTL issues not fixable by the PnR command. STOP and report:
  ```
  SYNTHESIS FAILED.
  Error output:
  <paste synth.sh stderr/stdout>

  Synthesis errors usually require fixing the Chisel source.
  Run `/chip-agent:workflow <description>` to regenerate, or manually fix the Verilog.
  ```
  (Do NOT retry synthesis failures -- they require RTL changes outside PnR scope)

**Step 2 -- Place and Route + GDS (with auto-fix retry)**
- Run: `<plugin-root>/scripts/pnr.sh <ModuleName>`
- On failure (non-zero exit -- structural PnR error): Read error output, report to user, STOP.
- On success (exit 0): Check timing by reading `MyDesign/<ModuleName>/workspace/pnr/reports/timing.rpt`
  - If timing MET (line contains "slack (MET)"): continue to Step 3
  - If timing VIOLATED (line contains "slack (VIOLATED)"): enter auto-fix loop:

  **Auto-fix: Timing Violation Recovery**
  1. Read current clock period from `MyDesign/<ModuleName>/workspace/spec.json` field `clock_period_ns` (default 2.0 if field absent)
  2. Increase period by 50% (e.g., 2.0 -> 3.0)
  3. Write updated `clock_period_ns` to spec.json using Edit tool (add field if absent, update if present)
  4. Re-run `<plugin-root>/scripts/synth.sh <ModuleName>` (synth.sh calls generate_sdc.sh which reads spec.json)
  5. Re-run `<plugin-root>/scripts/pnr.sh <ModuleName>`
  6. Check timing.rpt again
  7. Maximum 3 total attempts (initial + 2 retries). After 3 failures, STOP:
     ```
     PnR AUTO-FIX FAILED after 3 attempts.
     Timing still violated at clock period X.X ns.
     Final WNS: X.XX ns
     The module may need architectural changes to meet timing.
     ```

  CRITICAL: When adjusting clock period, re-run BOTH synth.sh AND pnr.sh. The SDC constraint affects both synthesis optimization and PnR STA. Skipping synthesis re-run makes the clock period change ineffective.

**Step 3 -- Format Report**
- Read the agent definition at `agents/pnr-report-formatter.md` (relative to plugin root)
- Follow the agent's rules to parse and format reports
- Present the formatted report to the user in the conversation

5. **Pipeline Stages table**:
| # | Stage | Description |
|---|-------|-------------|
| 0 | Verify Prerequisites | Check compiled Verilog exists for module |
| 1 | Synthesize | Run Yosys synthesis via synth.sh |
| 2 | Place and Route + GDS | Run OpenROAD PnR + KLayout GDS via pnr.sh, with timing auto-fix |
| 3 | Format Report | Parse raw reports into human-readable summary |

6. **Input section**: `$ARGUMENTS` -- A module name (PascalCase, e.g., `ALU`, `Counter8`). The module must already have compiled Verilog at `MyDesign/<ModuleName>/workspace/generated/<ModuleName>.v`.

7. **Output section**: List of artifacts produced:
- `workspace/pnr/<Module>.synth.v` -- gate-level netlist
- `workspace/pnr/<Module>.routed.def` -- routed DEF
- `workspace/pnr/<Module>.gds` -- final GDS layout
- `workspace/pnr/reports/` -- timing, power, area, synthesis, DRC reports
- Formatted PnR verification report (displayed in conversation)
