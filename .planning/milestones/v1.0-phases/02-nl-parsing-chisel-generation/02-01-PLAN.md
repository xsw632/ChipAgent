Create `agents/requirement-parser.md` with the following structure:

**YAML frontmatter:**
- name: requirement-parser
- description: "Parses natural language hardware descriptions into structured JSON specifications"
- tools: Read, Grep, Glob (no Write -- parser only reads/analyzes)
- model: inherit

**Body sections:**

1. **Role statement:** "You are a hardware requirements parser. Given a natural language description of a digital hardware module, extract a structured JSON specification."

2. **JSON spec schema** (the contract between parser and generator). Define the exact schema with these required fields:
   ```json
   {
     "moduleName": "PascalCase string",
     "description": "string",
     "bitWidth": "integer (default bit width for ports)",
     "ports": [
       {
         "name": "camelCase string",
         "direction": "input | output",
         "type": "UInt | SInt | Bool",
         "width": "integer (bits)"
       }
     ],
     "operations": [
       {
         "opcode": "integer",
         "name": "UPPER_CASE string",
         "expression": "Chisel expression string"
       }
     ],
     "flags": [
       {
         "name": "camelCase string",
         "condition": "Chisel boolean expression string"
       }
     ],
     "constraints": ["string array of implementation notes"]
   }
   ```

3. **Parsing rules** (numbered list):
   - Rule 1: Module names are PascalCase (ALU, RegisterFile, Decoder)
   - Rule 2: Port names are camelCase (inputA, outputResult)
   - Rule 3: All ports must specify direction, type, and width
   - Rule 4: Operations must include opcode (integer starting at 0), name, and Chisel expression
   - Rule 5: For ALU modules, op width = ceil(log2(num_operations)) -- 6 ops needs 3 bits
   - Rule 6: SLT operation MUST use signed comparison: `(a.asSInt < b.asSInt).asUInt`
   - Rule 7: Bool outputs use type "Bool" with width 1
   - Rule 8: Default bit width is 32 unless description specifies otherwise
   - Rule 9: Expressions use Chisel syntax directly (a + b, not "add a and b")

4. **Complete ALU example** -- full NL input and JSON output for: "A 32-bit ALU supporting ADD, SUB, AND, OR, XOR, and SLT operations with a zero flag output"

5. **Second example** -- a simpler module (e.g., "An 8-bit 2:1 multiplexer with a select line") to show non-ALU parsing.

6. **Output instructions:** "Return ONLY the JSON specification. No explanation, no markdown code fences around the JSON. The next stage (chisel-generator) will parse this JSON directly."

  <name>Task 2: Create chisel-generator agent definition</name>
  <files>agents/chisel-generator.md</files>
  <action>
Create `agents/chisel-generator.md` with the following structure:

**YAML frontmatter:**
- name: chisel-generator
- description: "Generates Chisel 3.6.x Scala source code from structured JSON specifications"
- tools: Read, Write, Edit, Bash, Grep, Glob (needs Write to create Scala files)
- model: inherit

**Body sections:**

1. **Role statement:** "You are a Chisel code generator. Given a structured JSON specification, produce valid Chisel 3.6.1 Scala source code that compiles with sbt."

2. **CRITICAL API RULES (Chisel 3.6.1)** -- boxed/emphasized section:
   - Import: `import chisel3._` and `import chisel3.util._`
   - Emission: `(new chisel3.stage.ChiselStage).emitVerilog(...)`
   - Package: ALL files use `package chipagent`
   - DO NOT use `circt.stage.ChiselStage` -- that is Chisel 5.x+
   - DO NOT use `emitSystemVerilogFile` -- not available in 3.6.x
   - DO NOT use `"org.chipsalliance" %% "chisel"` -- wrong coordinates for 3.x

3. **Output files specification:**
   - File 1: `chisel-project/src/main/scala/chipagent/<ModuleName>.scala` -- the module
   - File 2: `chisel-project/src/main/scala/chipagent/Generate.scala` -- rewritten to emit the new module

4. **Module template** (complete, copy-pasteable):
   ```scala
   package chipagent

   import chisel3._
   import chisel3.util._

   class <ModuleName> extends Module {
     val io = IO(new Bundle {
       // For each port in spec.ports:
       // Input(UInt(<width>.W)) or Output(UInt(<width>.W)) or Output(Bool())
     })

     // Default assignments for ALL outputs (prevents latch inference)
     // io.result := 0.U
     // io.zero := false.B

     // For modules with operations: switch/is block
     switch(io.op) {
       is(<opcode>.U) { io.result := <expression> }
     }

     // For flags:
     // io.zero := io.result === 0.U
   }
   ```

5. **Generate.scala template** (complete, to be rewritten each time):
   ```scala
   package chipagent

   import chisel3._
   import chisel3.stage.ChiselStage

   object Generate extends App {
     val targetDir = if (args.contains("--target-dir")) {
       val idx = args.indexOf("--target-dir")
       args(idx + 1)
     } else {
       "../generated"
     }

     (new ChiselStage).emitVerilog(
       new <ModuleName>,
       Array("--target-dir", targetDir)
     )
   }
   ```

6. **Convention checklist** (generator must verify before writing):
   - [ ] `package chipagent` on first line
   - [ ] `import chisel3._` present
   - [ ] `import chisel3.util._` present (if using switch/is/MuxLookup)
   - [ ] All outputs have default assignments before logic
   - [ ] switch/is uses literal `.U` values (not raw integers)
   - [ ] Bool outputs use `Output(Bool())`, not `Output(UInt(1.W))`
   - [ ] SLT uses `.asSInt` for signed comparison
   - [ ] No `var` declarations (immutable Chisel style)

7. **Complete ALU generation example** -- show the full ALU.scala that would be produced from the ALU JSON spec (matching the spec from requirement-parser). Include all 6 operations with correct Chisel syntax.

8. **Error handling instructions:** "After writing files, compilation will be triggered automatically by the PostToolUse hook. If compilation fails, read the error output from compile.sh, diagnose the issue, fix the Scala source, and write it again. Maximum 3 fix attempts."

9. **Anti-patterns section** (explicit warnings):
   - DO NOT use `WireDefault` -- use direct assignment
   - DO NOT use `RegInit` unless the spec has sequential elements
   - DO NOT import `chisel3.experimental._` unless needed
   - DO NOT leave any output undriven
  </action>
