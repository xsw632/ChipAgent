**Add a new section** to testbench-generator.md after "## Output Conventions" titled "## VCD Tracing Conventions" explaining:
- VCD traces are always generated (the simulation pipeline passes `--trace` to Verilator)
- The `<VCD_PATH>` placeholder in templates should be replaced with a path relative to where the simulation binary executes. Since `simulate.sh` runs the binary from the shell's CWD (NOT from obj_dir), and the binary is at `$OBJ_DIR/V$MODULE`, the testbench should write VCD to a path that resolves to `sim/logs/<ModuleName>.vcd` from the workspace. Use `"../logs/<ModuleName>.vcd"` as the relative path from obj_dir, OR write to a simple filename like `"trace.vcd"` and document that `simulate.sh` handles placement. DECISION: Use the simple approach -- write to `"trace.vcd"` in the current working directory (which is wherever simulate.sh invokes from). Then the debug agent will find it. Actually, per the CONTEXT.md decision, the VCD file should be at `workspace/<Module>/sim/logs/<Module>.vcd`. The simplest way: the testbench writes to a path that `simulate.sh` can predict. Since the binary runs from the simulate.sh CWD and simulate.sh already knows `$LOG_DIR`, have the testbench write to `"$LOG_DIR/$MODULE.vcd"` -- but that is a shell variable, not available to C++. Instead: the testbench-generator agent, when generating a testbench for a workspace module, should hardcode the VCD path as `../logs/<ModuleName>.vcd` (relative to obj_dir where the binary lives). Since simulate.sh runs `$OBJ_DIR/V$MODULE`, the binary's CWD is the shell's CWD (the directory from which simulate.sh was invoked), NOT obj_dir. This means the relative path approach is unreliable.

FINAL APPROACH (per RESEARCH.md Open Question 1): The testbench writes VCD to `"trace.vcd"` (current directory). Then `simulate.sh` moves it to `$LOG_DIR/$MODULE.vcd` after the simulation binary exits. Add 2 lines to simulate.sh after the simulation run (after the tee line, before the result check):
```bash
# Move VCD trace to logs directory if generated
[ -f trace.vcd ] && mv trace.vcd "$LOG_DIR/$MODULE.vcd"
```

In the testbench templates, use `tfp->open("trace.vcd");` consistently. In the VCD Tracing Conventions section, document that `simulate.sh` relocates the VCD file to `workspace/<Module>/sim/logs/<Module>.vcd`.

**Also update the Anti-Patterns section** to add:
- **DO NOT** forget `Verilated::traceEverOn(true)` before creating the VCD trace object -- without it, the VCD file will be empty (header only, no signal data)
- **DO NOT** forget `tfp->close()` before `dut->final()` -- the VCD file will be truncated if not properly closed
