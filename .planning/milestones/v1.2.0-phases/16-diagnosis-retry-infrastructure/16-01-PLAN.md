<objective>
Create the `diagnose_failure` MCP tool that classifies ORFS flow failures into error types and returns structured JSON with suggested parameter adjustments.

Purpose: This tool is the core intelligence for the retry infrastructure. It enables the Skill layer (Phase 17) to automatically diagnose why a PnR run failed and determine which parameters to adjust for the next attempt. Without this, failure diagnosis requires sending raw ORFS logs (5K-50K lines) to the LLM, wasting tokens and producing inconsistent results.

Output: `mcp-server/tools/diagnose-failure.ts` (tool implementation) and `mcp-server/tests/diagnose-failure.test.ts` (comprehensive unit tests)

    1. **DiagnosisResult interface** (readonly, immutable):
    ```typescript
    interface DiagnosisResult {
      readonly error_type: "timing_violation" | "congestion" | "drc" | "placement_overflow" | "synthesis_error" | "unknown";
      readonly severity: "critical" | "recoverable";
      readonly details: string;
      readonly suggested_params: {
        readonly clock_period_ns?: number;
        readonly place_density?: number;
        readonly core_utilization?: number;
      };
      readonly restart_from: "synth" | "floorplan" | "place" | "cts" | "route" | "finish";
    }
    ```

    2. **classifyError function** -- exported, pure function. Takes input object:
    ```typescript
    { stage: string; success: boolean; stderr: string; finish_wns?: number; drc_violations?: number; sdc_content?: string }
    ```
    Classification priority (most specific first):
    - stage="synth" + success=false -> synthesis_error, severity=critical, restart_from="synth"
    - stderr matches placement overflow regex -> placement_overflow, severity=recoverable, restart_from="floorplan"
    - stderr matches congestion regex -> congestion, severity=recoverable, restart_from="place"
    - drc_violations > 0 -> drc, severity=recoverable, restart_from="place"
    - finish_wns < 0 (or stage="finish" + success=true + wns < 0) -> timing_violation. Severity: check sdc_content for "virtual_clk" -> critical (combinational), else -> recoverable (sequential). restart_from="synth"
    - Fallback -> unknown, severity=critical

    3. **suggestParams function** -- exported, pure function. Takes error_type + current params. Returns new suggested params with bounds clamping:
    - timing_violation: clock_period_ns = clamp(current * 1.5, 1.0, 100.0)
    - congestion: place_density = clamp(current - 0.1, 0.30, 0.85)
    - drc: place_density = clamp(current - 0.05, 0.30, 0.85)
    - placement_overflow: core_utilization = clamp(current - 15, 20, 70)
    - synthesis_error/unknown: empty object

    4. **registerDiagnoseFailure function** -- registers MCP tool "diagnose_failure" with zod schema:
    - stage: z.enum(VALID_STAGES) -- which stage was running
    - success: z.boolean() -- whether the stage exited 0
    - stderr: z.string().optional().default("") -- stderr from run_stage
    - finish_report_content: z.string().optional() -- raw finish report text (tool will parse WNS)
    - drc_report_content: z.string().optional() -- raw DRC report text (tool will parse violations)
    - sdc_content: z.string().optional() -- SDC file content (for sequential/combinational detection)
    - current_clock_period_ns: z.number().optional().default(10) -- for computing suggestions
    - current_place_density: z.number().optional().default(0.6) -- for computing suggestions
    - current_core_utilization: z.number().optional().default(40) -- for computing suggestions

    The tool handler:
    a) If finish_report_content provided, parse WNS via parseFinishReport from get-report.ts
    b) If drc_report_content provided, parse violations via parseDrcReport from get-report.ts
    c) Call classifyError with parsed values
    d) Call suggestParams with classification + current params
    e) Return JSON result

    Import parseFinishReport and parseDrcReport from `./get-report.ts`. Do NOT duplicate parsing logic.
