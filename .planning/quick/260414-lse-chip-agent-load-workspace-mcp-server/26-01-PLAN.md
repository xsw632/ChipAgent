<objective>
Implement `/chip-agent:load_workspace` -- a slash command that detects the local workspace, fixes the broken MCP server path in `.mcp.json`, configures the MCP backend tools for Docker mode (since ORFS is not installed locally), and writes `~/.chipagent/workspace.json` for downstream consumption.

This enables the PnR pipeline to work: `/chip-agent:pnr` will call `check_environment` and `run_stage` via MCP, and those tools must know to use Docker when backend_mode=docker.
</objective>

## ORFS Docker Image Structure (confirmed by docker run)

The `openroad/orfs:latest` image has:
- ORFS flow at `/OpenROAD-flow-scripts/flow/` (container root)
- Makefile at `/OpenROAD-flow-scripts/flow/Makefile`
- sky130hd PDK bundled at `/OpenROAD-flow-scripts/flow/platforms/sky130hd/`

## workspace.json schema

The skill writes this file to `~/.chipagent/workspace.json` (absolute path to home directory):
```json
{
  "workspace_dir": "<absolute path to ChipAgent root>",
  "mcp_server_path": "<absolute path to mcp-server/index.ts>",
  "backend_mode": "docker" | "local",
  "docker_image": "openroad/orfs:latest",
  "docker_volumes": ["<workspace_dir>:/workspace"],
  "docker_workdir": "/OpenROAD-flow-scripts/flow",
  "orfs_flow_path": "/OpenROAD-flow-scripts/flow"
}
```

## Step A: Create the skill directory and file

Create `skills/load_workspace/SKILL.md` with these instructions:

1. **Find plugin root** by looking for `.claude-plugin/plugin.json` upward from cwd (same pattern as other skills).

2. **Read env.json** at `<plugin-root>/.chipagent/env.json`. Parse it. If it does not exist or `backend_mode` is absent, run `<plugin-root>/scripts/detect-env.sh` first.

3. **Find workspace root** -- use the plugin root as the workspace root (same as plugin root for this project).

4. **Fix `.mcp.json`**:
   - Read the current `.mcp.json` (at workspace root).
   - The `command` is `"node"` and the first `args` entry is the MCP server path.
   - Replace that path with `<workspace_root>/mcp-server/index.ts`.
   - Example: change `"/home/mingzhenjia/.claude/plugins/chip-agent/mcp-server/index.ts"` to `"/home/aa/snap/chipagent/chip/ChipAgent/mcp-server/index.ts"`.
   - Write the updated JSON back to `.mcp.json` using the Write tool.
   - Print a message telling the user to restart their Claude Code session (Claude Code reads .mcp.json at startup; a restart or `claude mcp restart` is needed for the new path to take effect).

5. **Read backend_mode** from env.json. If `"docker"`, update the MCP server tools (Steps 6-7). If `"local"`, skip Docker-specific steps.

6. **Update `mcp-server/tools/check-environment.ts`**:
   - Add a helper function `readWorkspaceConfig()` that reads `~/.chipagent/workspace.json` (use `os.homedir()` to resolve `~`).
   - The file may not exist yet; return `null` if absent.
   - In `registerCheckEnvironment()`, before calling `findOrfs()` and `findSky130hd()`, call `readWorkspaceConfig()`.
   - If `workspaceConfig?.backend_mode === "docker"`:
     - Set `orfs.installed = true`
     - Set `orfs.path = workspaceConfig.docker_workdir` (e.g., `/OpenROAD-flow-scripts/flow`)
     - Set `orfs.flow_path = workspaceConfig.orfs_flow_path`
     - Set `sky130hd.installed = true`
     - Set `sky130hd.path = join(workspaceConfig.docker_workdir, "platforms/sky130hd")`
     - Set `sky130hd.liberty = "lib/sky130_fd_sc_hd__tt_025C_1v80.lib"`
     - Set `sky130hd.tech_lef = "lef/sky130_fd_sc_hd.tlef"`
     - Set `sky130hd.cell_lef = "lef/sky130_fd_sc_hd_merged.lef"`
     - Set `sky130hd.gds = "gds/sky130_fd_sc_hd.gds"`
     - Set `backend_mode = "docker"`
   - Otherwise, fall through to existing filesystem detection (existing code).
   - The `docker` field: call `detectDocker()` as before (or report from workspace.json if available).

   Key import to add: `import { homedir } from "node:os"` at the top.

7. **Update `mcp-server/tools/run-stage.ts`**:
   - Add `import { homedir } from "node:os"` at the top.
   - Add a helper `readWorkspaceConfig()` that reads `~/.chipagent/workspace.json`.
   - Modify `registerRunStage()` to check `workspaceConfig?.backend_mode`:
     - If `"docker"`:
       - Construct the docker run command: `docker run --rm -v {workspace_dir}:/workspace -w {docker_workdir} {docker_image} make {stage} DESIGN_CONFIG={container_config_path}`
       - `workspace_dir` = `workspaceConfig.workspace_dir`
       - `container_config_path` = `/workspace/` + path relative to `workspace_dir` of `config_mk_path`
         (e.g., if `config_mk_path = /home/aa/snap/chipagent/chip/ChipAgent/MyDesign/ALU8/workspace/pnr/config.mk` and `workspace_dir = /home/aa/snap/chipagent/chip/ChipAgent`, then `container_config_path = /workspace/MyDesign/ALU8/workspace/pnr/config.mk`)
       - Use `spawn("docker", ["run", "--rm", "-v", `${workspace_dir}:/workspace`, "-w", docker_workdir, docker_image, "make", stage, `DESIGN_CONFIG=${container_config_path}`], { env, stdio: ["ignore", "pipe", "pipe"] })`
       - The `cwd` for log path still comes from `orfs_flow_path` (which is `/OpenROAD-flow-scripts/flow` -- the container path; this is used only for constructing the logPath string, not for actual spawning).
     - If `"local"` (or no workspace.json):
       - Use existing `spawn("make", ...)` behavior unchanged.
   - For the log path: use the `logPath` computed from `orfs_flow_path` as before (this is a string used in the response, not a filesystem path that needs to exist locally).

   Note: In Docker mode, ORFS writes results INSIDE the container's `/OpenROAD-flow-scripts/flow/results/` directory. The results are NOT persisted to the host unless we also volume-mount ORFS's results directory. However, ORFS reads DESIGN_CONFIG which points to `/workspace/...` containing the Verilog and config files. For now, the flow runs inside Docker and results are lost when the container exits -- this is acceptable for a first implementation. A future enhancement would volume-mount a results directory. Do NOT attempt to volume-mount results in this plan.

8. **Write `~/.chipagent/workspace.json`**:
   - Use Bash to get the home directory: `echo $HOME` or use `node -e "console.log(require('os').homedir())"`.
   - Write the JSON file with these exact fields (using the Write tool with the full path `~/.chipagent/workspace.json`):
     ```json
     {
       "workspace_dir": "<absolute workspace root>",
       "mcp_server_path": "<absolute path to mcp-server/index.ts>",
       "backend_mode": "<from env.json backend_mode>",
       "docker_image": "openroad/orfs:latest",
       "docker_volumes": ["<workspace_dir>:/workspace"],
       "docker_workdir": "/OpenROAD-flow-scripts/flow",
       "orfs_flow_path": "/OpenROAD-flow-scripts/flow"
     }
     ```
   - For `backend_mode=docker`: docker_workdir and orfs_flow_path are the container paths.
   - For `backend_mode=local`: use the orfs.flow_path from env.json for orfs_flow_path; docker fields can be omitted or set to empty strings.

9. **Confirm MCP server path is fixed**: After writing .mcp.json, confirm the new path exists with `test -f "<workspace>/mcp-server/index.ts"`.
